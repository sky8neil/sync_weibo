其它：`agent-twitter-client` 系列为 JS/且多为停滞分支；`Scweet` 等均为抓取向。Python 栈 + 发推 = **twifork** 是当前唯一「维护中且能发帖」的现成选择。

**twifork 要点（已实测）**
- `pip install twifork[impersonate]`；**drop-in 替换 twikit**（`from twikit import Client` 不变）。
- 本机已装好：`/home/fanfou-sender/.venv-tw`（Python 3.12 + twifork 2.4.0 + curl_cffi）。
- 冒烟通过：库完整（create/delete/is_logged_in/upload_media 全在）、网络通路 OK。
- 可选 `impersonate='chrome124'`（curl_cffi TLS 指纹）避免 v1.1 接口 403。

**关键事实（twifork 官方文档原话）**
> X has retired the onboarding flow that `Client.login()` drives … which requires a ~5 KB
> `$castle_token` generated by obfuscated in-page JavaScript and offers passkey/WebAuthn as
> a first factor. **None of that is reachable from a plain HTTP client, so password login
> cannot be made to work — no library fix will change it. Export your cookies from a browser
> session instead.**

→ 即：**密码登录在纯 HTTP 方案里已不可行**（这也是本机 2026-09-28 实测撞到的情况）；
正确姿势 = 从浏览器**导出一次 cookie**，之后长期复用。

## 二、封号风险说明（重点，摘自项目文档）

`twifork` 仓库内随附文档 **`ToProtectYourAccount.md`**（同时存在于原版 twikit）：

> Since this library uses an unofficial API, **your account may be banned if you use it
> incorrectly**. Therefore, please be sure to follow the measures below.

四条守则（原文转述 + 中文）：

1. **Avoid sending too many requests** —— 不要连发请求，注意冷却，别把自己打进 rate limit。
2. **Reuse login information** —— **反复调用 login 会被重点监控**（"logins, which are closely
   monitored"）；应当 `save_cookies` / `load_cookies` **长期复用登录信息**。
   - ⚠️ 这条正是本次实测教训：当天多次登录尝试触发了 X 的
     "We've temporarily limited your login. Please try again later."（约 1 小时自动解除）。
3. **Do not send too many messages** —— 不要过量发消息。
4. **Don't tweet sensitive content** —— 不发敏感内容（性、暴力、政治、歧视、仇恨等）。

README 补充：
> Issues that stem from X-side restrictions (**account suspension**, Cloudflare/IP blocks,
> captcha, automation limits) aren't fixable in the library and are out of scope.

**风险结论**：使用非官方通道存在账号被限制/封禁的可能（所有此类库皆然）；
但按上述守则（低频、cookie 复用、内容合规）用于**个人账号的正常发布频率**，属社区通行做法，
风险可控，且本项目仅用于单一账号的个人发布，不涉及批量/爬取。

参考链接：
- https://github.com/PawiX25/twifork （README + ToProtectYourAccount.md）
- https://github.com/vladkens/twscrape （抓取向，另见其 issue #175「Accounts survival rate」讨论）

## 三、采用方案与落地步骤

**架构**：浏览器导出 cookie（一次性）→ `state/tw_cookies.json` → 本机 `twitter_sender.py`
（基于 twifork 薄封装）→ 接入 multipost-api（`to=twitter`）→ 插件加按钮。

**Cookie 导出（用户操作，二选一）**
- 方法 A（DevTools）：登录 x.com → F12 → Application → Cookies → `https://x.com` →
  复制 **`auth_token`** 与 **`ct0`** 两个值。
- 方法 B（扩展）：安装 "Cookie-Editor" → Export → JSON → 提供内容。

**安全**：`auth_token`+`ct0` 等同于账号会话；仅存服务器本地（600 权限）。
如需吊销：X 设置 → 安全 → 「退出所有设备」。
